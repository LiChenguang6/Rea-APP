# refresh3 弹窗与启动等待修复（ARM64）

用户实机反馈：refresh1 可正常观看；安装 refresh2 后，开屏5秒、金币及视频切换广告弹窗仍然出现。refresh2 的代码路径测试不代表广告实际消失。本版继续处理独立窗口创建和续播路径。包名、私有数据目录与签名保持不变，版本码33，可覆盖 refresh1/refresh2，不要卸载或清除数据。

## 新增修改

所有位置来自本次提供的2.4.3 ARM64快照，使用完整 SHA-256 和原指令双重匹配。保留 refresh2 三处处理，新增如下改动，总计14条4字节指令：

- 启动弹窗队列：在 `0x813e58` 跳过 `LYa/open-screen-ads`，在 `0x814474` 跳过 `EYa/startup_gift.png` 活动礼包；同时跳过官方福利与两组竖屏推广的入队。队列、升级提示、系统公告、关闭和完成逻辑保留，不删除账户数据，不执行领币/领奖。
- 视频切换：`0x647dc0` 原本调用广告窗口方法 `0x647ddc`，关闭窗口后通过原回调调用 `0x815c24`。现直接使用相同控制器调用该原续播方法，保留前面的播放器重置和后续视频信息请求、权限判断、播放器初始化；不创建广告路由，因此不能调用会误关闭正常页面的 pop。
- 启动等待：原周期 Timer 的回调 `0x5a1678` 首次执行时，将纯广告计数归零，并在原调用位置 `0x5a16d4` 调用现有跳过动作 `0x7f5e8c`。仅移除该跳过动作的广告倒计时拦截，后面的初始化状态/失败提示与进入主页路径保留。Timer 的创建和释放不变。计数清零后后续 tick 不重复跳转或重复提示失败。通常在原 Timer 首次 tick（约1秒）尝试跳过；网络初始化时间不在此范围。

保留登录、账户与视频观看权限逻辑，不增加观看次数或金币，不改会员字段。Java 下载/管理/播放器捕获代码和原视频源配置保持原样。仅修改 ARM64，适配用户的 Redmi Turbo 4 Pro；其它 ABI 维持旧行为。

## 验证证据及边界

`tests/test_ad_patch.py` 用 Unicorn 执行实际 ARM64 修改路径，9项检查通过，包括：

- 修改仅限审核过的14条指令，未知快照拒绝处理；广告缓存与空列表路径。
- 五个推广窗口跳转到原下一个队列位置；升级、系统公告和队列完成代码逐字节保持一致。
- 视频切换实际调用原续播地址并传入相同接收对象，恢复栈；原取源和权限检查代码逐字节保持一致。
- 启动 Timer 使用正确状态调用现有跳过动作，仅调用一次；第二次 tick 不重复导航。Timer 创建代码、原初始化失败检查保持一致。

这些是合成指针/调用桩的指令执行检查，不是完整 Flutter UI 验收。签名、版本及全部库/assets打包审计见 `static-audit.json`、`update-compatibility.json`。云端无法访问真实源站，未证明手机上这三个弹窗全部消失；需要覆盖安装后实测。此前 refresh2 的失败反馈已保留，不能沿用其检查结果宣称完成。
