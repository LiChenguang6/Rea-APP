# refresh2 广告展示修复（ARM64）

用户确认 refresh1 已可在红米正常观看，本轮处理随新底包恢复的广告。包名、私有数据目录与签名不变，版本码32，可以覆盖 refresh1 安装；不要先卸载或清除数据。

## 范围和实现

对提供底包2.4.3的 ARM64 libapp.so 按 SHA-256 和原指令双重校验，仅替换三条4字节指令：

- `0x47ad4c → 0x47aec8`：仅针对本地 `advertisement` 广告缓存读取函数，走原有 null 返回路径。统一广告服务以及直接读广告缓存的调用方原本就包含 null / 空列表处理。缓存与账户数据不删除，原广告加载请求及启动初始化顺序保留。
- `0x807ee4`：独立广告站点接口的异步结果强制使用同函数原有的 `List<acb>(0)` 创建路径，保留 Future 类型和正常完成逻辑。
- `0x810fc8 → 0x811030`：另一广告站点控制器走原有空结果完成路径，不填充广告组件。

统一广告服务被开屏、弹窗、页面横幅／插入广告及播放器相关界面调用；实际覆盖效果仍待手机反馈。不承诺清除硬编码推荐、服务端混入普通内容的推广或视频文件内嵌广告。启动网络初始化和原有倒计时未改，可能仍需要等待或点击跳过。

只修改 ARM64（对应 Redmi Turbo 4 Pro）；ARMv7/x86_64 保持 refresh1 行为。本轮没有使用旧底包的地址。`libflutter.so`、其余原生库、全部 assets、原登录和视频观看权限逻辑保持原样。Java BetterPlayer 桥接及下载代码不变。

## 已验证与未验证

- 对完整快照哈希和三处指令的原始字节进行严格匹配，未知输入拒绝打补丁。
- Unicorn 执行实际 ARM64 修改路径：广告缓存返回原 Null 对象且恢复栈帧；空列表使用原有类型参数且长度为0；站点控制器进入原空完成路径。5项检查通过。该检查使用合成指针及分配桩，不等于整个 Flutter App 的运行测试。
- APK 构建、签名及与 refresh1 的证书兼容检查另见本次发布记录与 static-audit.json。打包审计核对全部原生库／assets；只允许上述三条指令变化。
- 云端无法访问原视频源，完整 ARM64 首页、广告消失和真实播放未复测。请在保留数据的情况下覆盖安装测试；若异常，可使用仓库历史中的 refresh1 安装包作为代码回退参考（Android 不允许普通降级安装，切勿为降级而卸载清数据）。
