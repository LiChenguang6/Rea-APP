# 映库 0.1.0 测试记录

测试时间：2026-10-22 UTC。测试包：`org.rea.cineshelf`，Android 8.0+，target SDK 35。

APK SHA-256：`fb71725d56dc263ed0ea14558a0011b8473bf36558f5d698e3f0942b44d694a6`

## 已完成

- AAPT2 / ECJ / D8 构建成功；zipalign 对齐；APK v2/v3 签名校验通过。复用已授权的新签名私钥，未更换密钥；私钥及密码不在公开仓库。
- Manifest 不请求任何联网或宽泛存储权限。测试组件与合成视频只存在于单独的测试 APK，不包含在播放器 APK。
- JVM 去重核心 10 项检查通过：精确副本、抽样碰撞而完整内容不同、长度不同、读取期间长度变化、不可读、取消、相似度平坦帧排除及不同长度排除等。
- Android 9 / API28 AOSP x86_64 软件模拟器，用 ffmpeg 生成的非色情合成素材完成一轮全新文件流程：4 个真实文件整理成 3 个条目；完整副本合并；转码版本只提示相似；虚拟入口读取字节数与原文件一致；另一个 App 在 URI 授权后成功读取 1,305,103 字节。
- Android MediaPlayer 实际打开合成 MP4；退出保存位置；重新打开从保存位置续播。
- 清理检查：副本被改写后拒绝删除，未删除任何文件；保留文件不能作为删除对象；核验后仅删除 1 个完整重复副本；剩余文件仍可定位；虚拟哈希入口及被删副本旧虚拟 ID 仍解析到保留文件。
- 强制停止播放器进程，再运行独立恢复测试：3 个条目、目录记录、完整哈希、虚拟入口、8,615 毫秒播放进度均从磁盘恢复。没有复用进程内 Catalog 实例。

本轮结果记录在源码包的 `core-test-results.txt`、`test-instrumentation.txt`、`test-logcat.txt`、`test-cold-restore.txt`。测试使用的文档格式 fixture 为独立测试提供器，不能单凭此断言所有 OEM 存储提供器行为一致。

## 验证范围与限制

云端没有 KVM，软件模拟器启动和安装较慢，曾出现系统界面 ANR。调试时曾连接 system_server 的 JDWP 并恢复 VM 运行以避免启动时看门狗重启；正式流程测试运行时已断开。曾隐藏模拟器系统错误弹窗，测试结果以日志和断言为准，不能把无弹窗当作无 ANR。正式 APK 不包含这些测试环境设置。

新播放器全部使用 Java / Android 系统 API，不含仅 ARM64 的原 App 库。x86_64 上的组件测试适用于上述逻辑，**不能替代 Redmi Turbo 4 Pro / HyperOS 实机测试**，也没有实测旧 App 的所有实际视频或任意编码。

没有执行旧版共享下载功能的最终验收；本项目已改为独立播放器。没有视频源下载、账户访问或权限破解逻辑。

虚拟入口通过 content URI 工作，不能透明代替旧 App 原文件路径。删除副本后，原 App 对应旧路径可能失效；不会创建假 MP4 误导原 App。转码相似提示可能误报、漏报，绝不用于自动删除。

GitHub 分发沿用用户允许的候选版流程；未做 APK 上传后的下载回读验证，不将上传成功写成功能验证。
